# 验证与故障排查

[配置指南](README.md) · [完整参考](reference.md)

一次只更改一组设置。保留先前的配置，并在进入下一个集成之前验证实际的用户操作。

## 检查服务是否已启动

对于本地试用，打开 `http://localhost:8000/health`。对于托管服务，请使用运维人员提供的相应 API 健康地址。

除了顶层状态，还要阅读各个条目。当前端点将整体 HTTP 成功建立在数据库连接上；Redis 或 Chroma 可以报告 `down`，而整体状态仍为 `ok`。标记为 `not_configured` 的 Redis 条目意味着它被有意省略。

健康检查不会验证模型密钥、每个业务连接器、客服可用性、渠道回复送达，也不会验证所有上传的文档都已恢复到搜索索引。

## 运行一个简短的验收检查

| 更改的方面 | 要检查什么 | 什么能确立成功 |
| --- | --- | --- |
| 基础配置 | 打开健康检查，登录，创建会话 | 使用了正确的数据库和账号 |
| 功能 | 检查 **插件与能力**，然后使用客户页面 | 预期的后端功能加载，匹配的 Web 链接可用 |
| 知识/模型 | 提出一个已知问题并检查引用/提供商请求 | 检索到正确的文档并确认预期的模型路径 |
| 持久化 | 在受控试用中重启，并就同一文档提问 | 记录和所需的搜索行为得到恢复 |
| 客服 | 请求人工、以客服身份认领、回复、交还 AI | 正确的范围内客服访问和已保存消息 |
| 订单查询 | 测试本人拥有的、非本人的和不可用的订单 | 仅对经过授权的匹配订单返回已验证的真实状态 |
| 通知 | 触发一个预期的测试事件 | 接收系统确认预期事件和签名 |
| SSO | 以多个预期角色登录 | 正确的账号匹配和权限 |
| 微件/渠道 | 发送一条真实消息并测试后续 | 回复在预期渠道中可见，而不仅仅是服务器日志中 |

## 配置没有生效

1. 在参考中检查确切的设置名称。未知键可能被忽略。
2. 检查该设置属于 API 环境，而不是 Web 构建或数据库记录。
3. 确认 API 从包含预期 `.env` 的文件夹启动。
4. 检查是否有导出的 shell 值或托管面板值覆盖了该文件。
5. 重启每个受影响的 API 进程，或为前端设置重新构建 Web 应用。
6. 检查该设置是仅影响新工作，还是被记录为保留/部分集成。

对于本地 shell 覆盖，`unset SETTING_NAME` 会在下次启动前移除该命名覆盖。将 `SETTING_NAME` 替换为实际名称；不要清除无关的环境值。

## 常见的配置失败

| 症状 | 可能的原因和下一步 |
| --- | --- |
| 启动拒绝弱密钥 | 生成真实的 `SECRET_KEY`，将其应用到 API 进程并重启。不要通过禁用生产模式来绕过检查。 |
| 启动拒绝 `OIDC_MOCK` | 为 staging/production 移除 mock 模式，并改为配置经过验证的身份。 |
| 启动报告设置/JSON 解析错误 | 检查布尔值、数字，尤其是 `CORS_ORIGINS` 的 JSON 语法。使用普通引号，而不是文字处理软件的引号。 |
| 未知 profile/插件或找不到清单 | 使用现有的 ID，并在打包应用时保留仓库的 `packages/contracts/features.yaml`。 |
| 所有账号似乎都消失了 | 检查工作目录和 `DATABASE_URL`；可能创建了不同的 SQLite 文件。在定位到保留的数据库之前，不要注册替代账号。 |
| 数据库连接被拒绝 | 验证实际的主机、端口、凭据、服务就绪状态和 API 的网络。在容器内，`localhost` 指的是该容器。 |
| 迁移提示表已存在 | 让运维人员核对 schema 和 Alembic 历史；不要删除保留的数据库或盲目标记修订。 |
| 网页打开但请求失败 | 检查 API 进程、`/api` 的代理、WebSocket 升级，以及未更改的 `/api/v1` 前缀。`VITE_API_URL` 未实现。 |
| 浏览器报告 CORS 拒绝 | 将确切的页面来源作为条目添加到 JSON 列表，重启，并验证代理/地址设置。 |
| 客户的工单菜单消失 | 当前的自动功能发现需要客服/管理员；请使用匹配的非机密 `VITE_ASKFLOW_FEATURES` 列表并重新构建/重启 Web 应用。 |
| 已移除的插件仍处于启用状态 | 某个依赖插件把它添加了回来。检查依赖项，并也移除相关的依赖方。 |
| 模型请求返回 404 | 检查模型基础地址不包含 `/v1` 或完整端点；客户端会追加自己的路径。 |
| 模型请求返回 401/403 或未知模型 | 私下验证提供商凭据、权限和确切的模型 ID。 |
| 对话模型可用但上传失败 | 远程嵌入可能因回退到对话凭据而被激活。配置受支持的嵌入服务和模型。 |
| Chroma 报告维度错误 | 旧嵌入和新嵌入可能不同。使用兼容的集合并为每个相关文档重建索引。 |
| 健康检查正常但重启后文档搜索失败 | 进程本地索引可能为空。安排重建索引/索引恢复；数据库列表不能证明搜索索引已填充。 |
| 配置了 Chroma 但健康检查显示 memory/失败 | 检查 `.[vector]` 的安装、主机/端口或目录权限，以及运维人员日志。内存回退不是持久化的成功。 |
| 配置 S3 后文件仍保留在本地 | 预期行为：标准存储适配器不使用 S3 字段。请保留本地上传文件。 |
| 文档一直处于待处理状态 | 检查 `INDEX_ASYNC`、worker 可用性、测试模式和队列故障。不要反复上传重复文件。 |
| 订单任务已受理但没有结果出现 | 刷新会话；检查 agent 功能、任务开关、非测试模式、数据库 worker、端点和 ID 匹配。 |
| 更改通用 `order_status` 连接器对任务没有效果 | 已保存任务的订单查询使用 `ORDER_LOOKUP_URL`，而不是该数据库连接器记录。 |
| 移除目标没有停止排队的工作 | 允许列表控制新接收。请使用适当的任务控制；禁用/重启 worker 不会撤销外部操作。 |
| 没有人看到排队的人工请求 | 验证客服角色、已启用的团队管理功能、成员资格和意图范围。 |
| SLA/转人工作业从不运行 | 检查 `SWEEPER_ENABLED`、模式和实际运行的进程；间隔最小为 15 秒。 |
| 通知标记为 `sent_sink` | 没有配置外部 URL；请设置真实的接收方并验证送达。 |
| 即时通讯回调成功但用户看不到回复 | 初始接收和出站送达不同；检查所选适配器是否实现并配置了平台的回复模式。 |
| 语言/机器人/MCP 设置似乎无效 | 检查其文档化的集成边界；这些设置不会创建已翻译的 UI、安全机器人知识分区或远程工具连接。 |

## 恢复先前的配置

对于普通限制、路由设置和功能选择，请在原始位置恢复先前的值，并视情况重启/重新构建。用新请求再次测试。

对于存储或嵌入更改，请与运维人员一起恢复配置和数据/索引状态的一致组合。返回到旧数据库可能会遗漏较新的记录。恢复机密也可能改变哪些已颁发的登录仍然有效。已经执行的外部操作无法通过回滚 `.env` 来撤销。

## 寻求帮助

告诉运维人员你更改了哪些设置名称、哪个页面或进程失败、确切的错误、时间和时区，以及你如何验证。在有帮助时包含 profile、环境模式以及非机密的主机/端口详情。

不要附上整个 `.env`、访问令牌响应或凭据截图。从连接字符串中删除密码和令牌。对于源代码缺陷，运维人员可以使用项目的 [问题跟踪器](https://github.com/RightCloudhub/AskFlow/issues)。

关于操作流程，请参见 [模型/存储维护](../../deploy/runbooks/reindex-model-storage.md)、[性能与内存](../../deploy/runbooks/performance-and-memory.md) 和 [监控](../observability/monitoring.md)。
