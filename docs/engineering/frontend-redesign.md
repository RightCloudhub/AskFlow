# AskFlow 前端重构说明

本次为源码重构，覆盖客服、认证、工单、管理控制台、商城和嵌入客服。
按用户的 `code only` 要求，没有运行预览、构建、测试、代码度量或浏览器检查。
视觉表现、交互回归与类型检查均待验证。

## 设计方向

采用 taste-skill 应用屏幕方向中的 Achromatic ledger：浅冷灰工作背景、白色内容面、
深石板色主操作，以及用于数据和状态的克制青绿色。
布局围绕 AskFlow 的“问题 → 回答依据 → 后续服务”组织，让对话、工单、订单和运营记录相连。
没有生成最终方向表或 seed，也没有获得前后截图、检查分数或浏览器检测结果。

参考 Intercom 的服务上下文、Linear 的导航与记录优先级、Shopify Admin 的商品和订单工作流惯例。
这些是设计参照，未进行外部网站实测或复制页面。

## 统一基础

- `apps/web/src/design/tokens.ts` 定义主色、语义色、字体、间距、圆角和浮层阴影。
- `ConfigProvider` 使用这些 token 配置 Ant Design 组件。
- `TokenBridge` 从当前 Ant Design token 派生根级 CSS 变量，定制界面和门户浮层共享主题。
- 内容面用背景层级和细边界区分；阴影用于浮层，统计数字使用等宽数字特性。
- 使用系统中文字体回退，不新增字体、图片或组件依赖。

## 数据与响应式原则

所有业务数量、金额、图片和来源来自已有 API。缺失值显示“—”，与真实零值区分。
现有接口没有时间序列，因此展示分布条形图和环形图，不生成虚构趋势或演示统计。
商城订单图的各项累计指标可能重叠，界面明确说明统计口径。
表格保持一致行背景，用悬停和状态强化定位，不使用斑马纹。

窄屏将编辑旁栏和结算区转为纵向，导航进入抽屉，FAQ 与工单看板降低列数。
对话的咨询详情栏在较窄桌面隐藏，消息中的引用入口继续可用。
保留加载、空态、错误与重试，减少动态效果，并尊重系统减少动画偏好。
