# 管理工作区与分步表单

## 本轮边界

采用单部署内的账号角色、栏目和操作隔离。用户已确认企业级多租户数据隔离不在本轮实施范围。
数据库仍为单租户；工作区地址不能作为数据租户标识或授权来源。

## 实施结构

| 工作区 | 地址 | 内容 |
| --- | --- | --- |
| 客服运营 | `/admin/service` | 人工接管、工单、技能组、SLA、知识、质检、商城客服 |
| 商城管理 | `/admin/commerce` | 商品、库存、订单、支付、财务、邀请风控、通知 |
| 系统管理 | `/admin/system` | 账号、角色授权、配置、审计、提示词、连接器、运行记录、基础设施 |

`/admin` 展示当前账号可用的工作区；只有一个工作区时直接进入。
各工作区保留自己的导航和首页，全局查找与切换器只包含有权访问的页面。
旧 `/admin/handoffs`、`/admin/mall/catalog` 等地址重定向到对应工作区，保留查询参数和锚点。

授权来自登录身份和后端返回的权限集合，功能开关仅控制是否装配页面。
`AdminAccessGate` 在挂载业务页面前校验权限，拒绝直接输入未授权地址。
普通用户无管理入口；座席可进入人工接管、工单及其商城基础权限对应的栏目；
系统管理员拥有管理权限；自定义角色按 `catalog:write`、`rbac:write` 等显式权限展示栏目和操作。
基础设施接口与页面统一要求系统管理员。

后端依赖继续逐请求执行 `require_admin`、`require_agent_or_admin` 或 `require(permission)`，
前端隐藏按钮不代替接口授权。身份与授权在前台每 30 秒及窗口重新聚焦时刷新；
服务端撤销权限立即作用于后续请求。切换账号清除查询缓存、表单状态和聊天连接。

## 分步交互

共享 `GuidedForm` 管理逐步校验、返回修改、保留输入、核对提交、键盘焦点和重复提交锁。
只有最后一次确认触发写入；没有输入项的管理操作也显示操作对象并等待确认。
已有工单、地址、商城长表单与提示词使用相同流程；知识草稿和通知偏好补齐分步编辑。
通知偏好可选择夜间免打扰或全天接收，验证跨午夜时间范围，并保留已有设置的时区。

管理操作先选择业务记录，再填写变更。记录编号与乐观锁版本自动带入；
用户与角色使用选择器，金额以元输入、以分提交，日期使用日期时间控件。
新建通知模板使用版本 0；编辑时从受 `notify:write` 保护的模板目录读取最新版本与正文，
绑定事件和语言。版本冲突交由后端拒绝，用户刷新后重新核对。

## 验证入口

- 前端：`cd apps/web && npm run build && npm run test:mall`
- 接口：`cd apps/api && .venv/bin/python -m pytest tests/mall/test_workspace_permissions.py tests/mall/test_role_directory.py tests/mall/test_notification_template_directory.py`
- 浏览器：先构建，然后在 `scripts/e2e` 运行 `npm run preview:admin`，另一个终端运行 `npm run test:admin`。

浏览器预览仅绑定回环地址、使用明确的测试数据，写入必须由测试显式拦截；不会连接业务数据。
浏览器用例覆盖角色矩阵、直接地址拒绝、会话切换、权限读取失败与重试、
分步填写与返回、提交内容、角色撤销确认、旧地址兼容及手机导航。
测试数据位于 `scripts/e2e/admin-fixtures.mjs`，不进入应用构建。

视觉沿用已选 Framed sheet 方向（seed 614084058）及现有品牌字体与颜色，不重新抽取方向。
本轮不新增展示用业务数据、图片或统计数字。
