# 管理

[用户指南](README.md) · 上一篇：[知识管理](knowledge.md) · 下一篇：[报表与服务监控](reports.md)

管理员负责管理服务的内容、访问权限和设置。本指南涵盖浏览器中的控件。安装和运行 AskFlow 的人还负责服务器配置和集成；这可能是另一个人。

关于配置文件、确切的设置名称、默认值、连接设置和重启说明，请使用 [配置指南](../configuration/README.md)。

## 准备新服务

在你的技术运维人员提供一个可用的网站之后：

1. 获取一个管理员账号，并确认你可以打开 `/admin/users`。
2. 打开 **插件与能力 (Plugins and capabilities)**，查看启用了哪些功能。
3. 使用 [知识管理](knowledge.md) 添加一份已批准的文档，然后测试一个它能回答的问题。
4. 让运维人员安排客服账号和角色。将客服添加到适当的技能组。
5. 使用一个客户账号请求人工，然后使用单独的客服会话认领并回答它。
6. 创建一张示例工单，并核实客服可以更改其状态。
7. 如果启用了订单查询，请让运维人员在客户依赖它之前，对照实际业务服务进行验证。
8. 与用户分享网址、登录说明、支持的主题、支持时间和升级联系人。

客户和客服试用时请使用不同的浏览器配置文件或浏览器，以免以一个身份登录时替换另一个身份的会话。你的技术运维人员可以使用 [试点部署检查清单](../../deploy/checklists/pilot-integration.md) 进行环境检查。

## 了解账号角色

| 角色 | 典型访问权限 |
| --- | --- |
| `user` — 客户 | 自己的会话和工单；通过受支持的集成访问自己的任务/偏好数据 |
| `agent` — 人工客服人员 | 客户能力、客服工单、范围内的接管队列、团队信息和能力信息 |
| `admin` — 管理员 | 客服能力，加上知识、设置、用户管理、报表和治理 |

菜单可见性遵循已启用的功能，并不完全按角色过滤。可见的按钮或页面并不证明该账号可以执行其操作。**需要管理员 (Admin required)** 意味着必须由管理员执行该操作；反复点击按钮并不能改变这一点。

## 管理账号

打开 **系统治理 → 用户管理 (System governance → User management)**，位于 `/admin/users`。

1. 通过用户名和电子邮件找到用户。
2. 检查 **角色 (Role)** 和 **状态 (Status)**。
3. 点击 **禁用 (Disable)** 阻止访问，或点击 **启用 (Enable)** 恢复访问。
4. 检查结果状态。

这些操作会立即生效。在禁用账号前请仔细核对，尤其是当它属于你自己或是唯一可用的管理员账号时。禁用账号会保留其记录；这不是数据删除。

界面会列出角色，但不编辑角色。它也没有账号创建、密码重置、SSO 配置或数据导出/删除控件。请与你的安装运维人员安排角色更改和账号恢复。关于个人数据请求，请参见 [隐私与已保存偏好](privacy.md)。

## 创建支持技能组

技能组决定客服可以处理哪些排队请求。

1. 打开 **客服运营 → 技能组 (Service operations → Skill groups)**，位于 `/admin/teams`。
2. 在 **名称 (Name)** 中，输入一个易于识别的团队名称。
3. 在 **意图范围（逗号分隔） (Request types, comma-separated)** 中，输入内部请求类型名称，例如 `complaint,fault_report,handoff`。
4. 点击 **创建 (Create)**。
5. 在团队的 **添加成员 (Add member)** 选择器中，选择一个客服账号。选择会立即添加该成员。
6. 检查成员数量，并让该客服刷新其接管收件箱。

常见的请求类型有 `faq`（一般问题）、`product`（产品问题）、`order_query`（订单查询）、`fault_report`（故障报告）、`complaint`（投诉）和 `handoff`（请求人工）。

请求类型范围为空会使该团队成为排队请求的兜底团队。没有团队归属的客服看不到新入队的接管请求。将客户账号添加到组中不会赋予其客服角色。

标准页面可以创建组并添加成员。它不提供编辑、移除成员或成员详情界面。请让运维人员通过组织的管理流程进行更正。

## 更改请求的处理方式

**意图（intent）** 是客户想要的帮助类型。**路由（route）** 是响应方法。

打开 **智能配置 → 意图路由 (Intelligent configuration → Intent routing)**，位于 `/admin/intents`。

1. 记录现有映射，以便可以恢复。
2. 在 **更新映射 (Update mapping)** 中选择一个 **意图 (Intent)** 和 **路由 (Route)**。
3. 点击 **保存 (Save)**，并检查成功消息和当前映射。
4. 测试一个有代表性的客户问题。

| 路由选择 | 效果 |
| --- | --- |
| **知识问答 / rag** | 搜索知识并据此作答 |
| **工具调用 / tool** | 使用可用的业务工具 |
| **建单 / ticket** | 创建或查找工单 |
| **转人工 / handoff** | 请求人工支持 |
| **澄清 / clarify** | 向客户询问更多细节 |

已保存的映射无需重启服务即可生效。选择工具路由不会安装或连接业务工具。某些已启用的后台目标（例如订单查询）会在此映射之前处理；更改表格不会重新配置每一个服务任务行为。

**当前映射 (Current mapping)** 表为空可能意味着没有保存任何自定义覆盖。内置处理仍然存在。要撤销映射更改，请选择之前的路径并再次保存。

## 更改回复指令

**提示词模板（prompt template）** 包含自动助手用于受支持目的的指令。将其用于已批准的措辞和回复行为；将面向客户的事实和政策放入知识库。

1. 打开 **智能配置 → 提示词模板 (Prompt templates)**，位于 `/admin/prompts`。
2. 通过输入确切的 **模板 Key (Template key)** 选择已知模板。使用列表；`rag.system` 是标准知识回答指令的键。
3. 点击 **加载当前版本 (Load current version)** 并保留当前内容的副本。
4. 编辑 **提示词正文 (Template body)**。
5. 点击 **发布并激活 (Publish and activate)**。
6. 检查活动内容预览，并测试有代表性的问题。

发布会创建一个版本并立即激活它。此界面中没有额外的草稿批准步骤。要通过页面恢复以前的措辞，请粘贴你保留的副本并将其作为新版本发布。

任意的新键不会创建新能力。模板也无法凌驾于内置权限检查或证据要求之上。如果更改模板似乎没有效果，请让运维人员检查相关响应路径是否使用它。

## 检查业务连接

**连接器（connector）** 将 AskFlow 链接到另一个业务服务。打开 **系统治理 → 业务连接器 (Business connectors)**，位于 `/admin/connectors`，查看名称、地址、启用状态和描述。

**试调用 (Test call)** 会实际调用所选连接器并显示其响应。它不是编辑或配置按钮。该页面不发送自定义输入参数，因此仅对运维人员已确认适合测试的连接器使用它。返回错误或 mock 结果并不证明真实的客户操作成功。

该页面没有创建、编辑、凭据或启用/禁用控件。请让你的技术运维人员配置连接，并执行需要特定输入的测试。

## 检查已启用的功能

打开 **系统治理 → 插件与能力 (Plugins and capabilities)**，位于 `/admin/plugins`。

- **Profile** 是安装所选的功能包。
- **启用 (Enabled)** 表示该功能已在配置中被选中。
- **已加载 (Loaded)** 表示正在运行的服务已加载它。
- **依赖 (Dependencies)** 列出它需要的其他功能。

该界面是只读的。它不是应用商店，也没有安装或启用开关。请让运维人员更改部署配置，并在需要时重启服务。之后刷新浏览器。

已启用的连接器或渠道功能仍然需要配置其外部服务。如果 profile 显示 `unknown`，或预期功能缺失，请重新加载一次，如果问题仍然存在则报告。

## 记录服务变更

打开 **系统治理 → 上线卡片 (Launch cards)**，位于 `/admin/launch-cards`，输入 **变更标题 (Change title)**，然后点击 **创建 (Create)**。

该列表跟踪变更记录，以及预期的与实测的 FAQ 解决率。创建卡片不会部署软件或衡量客户结果。当前表单提供一个默认预期解决率 70%；它不是实测结果，也不是针对你组织的建议。

浏览器页面可以创建和列出卡片。更新其状态、预期指标和实测值需要组织的管理集成或运维人员。
