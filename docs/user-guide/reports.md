# 报表与服务监控

[用户指南](README.md) · 上一篇：[管理](administration.md) · 下一篇：[其他对话方式](channels.md)

这些页面需要管理员账号及其相关功能。它们帮助你决定要调查什么。它们不能替代检查客户的实际问题。

## 查看服务工作量

打开 **运营总览 → 运营看板 (Overview → Operations dashboard)**，位于 `/admin`。

| 指标 | 它告诉你的信息 | 有用的后续操作 |
| --- | --- | --- |
| 消息数 | 已保存消息的数量，包括不同的消息角色 | 了解整体活动；这不是客户数量 |
| 未关闭工单 | 标记为待处理或处理中的工单 | 查看 **工单中心 (Ticket center)** |
| 排队接管 | 等待客服认领的请求 | 检查人员配置和 **人工接管 (Human handoff)** |
| 未关闭知识缺口 | 已记录且仍未解决的无答案问题 | 查看 **知识缺口 (Knowledge gaps)** |
| SLA 违约 | 标记为未达服务目标的工单 | 查看 **SLA 监控 (SLA monitoring)** |
| 负面反馈 | 已记录的负面反馈条目 | 调查质量和客户关切 |
| 接管超时 | 超时的接管记录 | 检查队列覆盖和响应安排 |
| 预估成本 | 已记录的模型成本估算，以美元计 | 查看 **成本分析 (Cost analysis)** |

看板结合了存储的总数和当前状态计数。它不提供日期范围选择器或按天趋势报表。不要把每个数字都理解为“今天的活动”。风险图中的类别可能重叠；它们的总和不一定是不同客户或事件的数量。

## 检查服务时间目标

**SLA**（服务级别协议）描述服务目标，例如客服应多快响应或解决工单。实际目标由你的组织设定。

1. 打开 **客服运营 → SLA 监控 (SLA monitoring)**，位于 `/admin/sla`。
2. 查看计数和 **预警 / 违约工单 (Warning / breached tickets)**。
3. 如果你需要立即运行检查，请点击 **立即扫描并通知 (Scan and notify now)**。
4. 阅读 **最近扫描 (Latest scan)**，了解状态变化及其原因。
5. 在 **工单中心** 中跟进相关工单。

| SLA 状态 | 含义 |
| --- | --- |
| `ok` / **正常** | 当前没有记录到预警或违约 |
| `warning` / **预警** | 服务目标即将到期 |
| `breached` / **违约** | 已错过服务目标 |

**立即扫描并通知** 会执行扫描，并可能通过已配置的渠道发送通知。它不只是刷新页面。所列的变化是那次扫描发现的状态变化，而不是检查的工单总数。通知的可用性和送达取决于你的安装。

该界面显示已存储的 SLA 状态；也请检查每张工单的当前状态。其默认的预警/违约列表限制为 50 条记录，因此更大的数量可能无法全部显示。目标配置和通知目的地在本页面之外管理。

## 调查答案质量

打开 **运营总览 → 质检中心 (Quality center)**，位于 `/admin/qc`。

该页面显示平均质量分、已记录的助手运行数、拒答率、反馈，以及低分或拒答运行的列表。

质量分使用基于已记录拒答和警告标签的固定规则。它不是对事实正确性的人工评估，也不是第二次 AI 审查。即使拒绝回答是恰当的，一次合理的拒答也可能降低分数。平均值当前使用最多 100 条已保存运行的有限样本；低分列表同样有限。

将低分作为调查的起点：

1. 记下该行的 **Run ID**、路由、请求类型、拒答指示和 **Flags**。
2. 打开 **运行回放 (Run replay)**，查找该 Run ID。
3. 检查问题是否涉及知识缺失、客户输入不清或已连接服务故障。
4. 更正源材料或联系相关运维人员，然后测试受影响的情景。

反馈率使用受支持界面实际记录的反馈。标准客户对话页面当前没有点赞/点踩控件，因此没有反馈并不意味着每位客户都满意。

## 阅读一次已保存的运行

打开 **运营总览 → 运行回放 (Run replay)**，位于 `/admin/agent-runs`。

点击某次近期运行旁的 **回放 (Replay)**，或将其标识符粘贴到搜索框并点击 **查询 (Search)**。查看响应方式、请求类型、拒答状态、步骤和成本信息。

**运行（run）** 是一次已记录的处理消息的尝试。**Flags** 是关于发生了什么情况的诊断标签。**JSON** 是用于可展开细节的结构化文本格式；你可以把它交给技术支持，而无需理解每个字段。

回放显示已保存的记录。它不会重新发送客户的消息或重复业务操作。它不是完整的服务任务管理界面；缺少运行条目并不证明不存在后台任务。

## 阅读模型成本

打开 **运营总览 → 成本分析 (Cost analysis)**，位于 `/admin/costs`。

该页面按用途和模型对已记录的调用进行分组。**输入 token** 衡量发送给语言模型的文本片段；**输出 token** 衡量它返回的文本片段。Token 不等同于单词、消息或客户。

金额是基于可用用量和价格信息的美元估算。它们不是发票，可能遗漏未记录的调用或其他运营成本。缺少记录或估算为零并不证明整个服务是免费的。

如果某个用途或模型变得意外昂贵，请让运维人员检查其用量和定价配置。此界面不选择模型、不设定预算，也不强制执行支出限制。

## 查看已记录的管理操作

打开 **系统治理 → 审计日志 (Audit logs)**，位于 `/admin/audit`。

找到相关的操作、资源和时间戳，然后展开 **查看 JSON (View JSON)** 阅读其详情。审计记录有助于解释文档删除、账号更改或其他已记录的操作。它们不是每次交互的完整记录。

该页面没有筛选或导出控件。对于你无法找到的记录，请向管理员或运维人员提供大致时间、受影响的资源和你正在调查的操作。报告时间时请注明时区，因为有些页面显示原始存储的时间戳。
