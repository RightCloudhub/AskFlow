# 与 AskFlow 对话

[用户指南](README.md) · 上一篇：[快速上手](getting-started.md) · 下一篇：[你的工单](tickets.md)

## 提出有用的问题

说明你想做什么，并包含识别问题所需的细节。日常语言即可。一次只提一个请求。

| 不要这样说 | 试着这样说 |
| --- | --- |
| “它不工作。” | “我提交订单时，支付页面显示错误 E12。” |
| “它在哪？” | “请查一下订单 12345678 的配送状态。” |
| “退货？” | “未拆封的商品可以退吗？时限是多久？” |

上面的订单号只是示例：请替换为你实际的订单号。这些示例并不表示你的组织拥有那些产品、政策或已连接的服务。

相关的后续问题请使用同一会话。不同的问题请开始新会话。对于较长的讨论，请重述重要细节，而不要假设助手仍然掌握较早的每条消息。

标准消息框只接受文本。它没有附件或语音消息控件。请用文字描述相关信息；如需发送文件，请向客服询问批准的方式。

## 理解回复

AskFlow 可以通过几种方式回复：

| 回复 | 含义 | 下一步 |
| --- | --- | --- |
| 带引用的答案 | 它在知识库中找到了支持答案的段落 | 阅读答案并查看相关引用 |
| 请求提供细节 | 它需要更多信息 | 在同一会话中回复所请求的细节 |
| 拒答或不确定消息 | 它无法提供有支持的答案或处理请求 | 重新表述、提供细节，或请求人工支持 |
| 请求已受理消息 | 它已记录要执行的工作 | 等待结果；仅受理并不等于完成 |
| 工单确认 | 已创建或找到一条跟进记录 | 打开 **工单 (Tickets)** 并查看该记录 |
| 人工支持消息 | 会话已进入客服队列 | 在同一会话中继续 |

AskFlow 使用你的组织提供的信息和服务。它不会自动了解你组织的全部政策，不会搜索公共互联网，也无法访问每一个业务系统。

会话列表也可能显示一个状态：

| 会话状态 | 含义 |
| --- | --- |
| `active` | 可供自动处理 |
| `transferred` | 正在人工支持处理中，包括等待客服认领 |
| `closed` | 已标记为关闭；如仍需帮助，请开始新会话 |

标准对话页面没有关闭或重新打开会话的控件。这些标签描述的是会话，而不是工单或订单请求的进度。

## 查看引用

有些答案包含诸如 `[1]` 和 `[2]` 的标记。

1. 点击答案下方的 **查看引用 · N (View references · N)**。
2. 在侧边面板中找到对应编号的段落。
3. 检查其文档标题和措辞是否适用于你的情况。
4. 完成后关闭面板。

面板显示来源名称和截取的文本片段。它不提供整份文档下载，也不是可搜索的文档库。如果你需要完整政策，请联系你组织的支持团队。

来源旁边可能显示一个较小的分数。它描述的是搜索匹配程度；它不是客户评分，也不保证政策是最新的。如果答案与其引用冲突，请告诉客服你问了什么，以及哪个来源似乎不正确。

## 理解置信度和路由标签

**置信度 (Confidence)** 是系统对答案支持程度的估计。它不是答案正确与否的实测概率。即使数值很高，仍然需要阅读实际答案和证据。

你还可能看到这些简短标签：

| 标签 | 通俗含义 |
| --- | --- |
| `rag` | 基于检索到的知识段落给出的答案 |
| `tool` | 业务查询或其他已连接的操作 |
| `ticket` | 与工单相关的回复 |
| `handoff` | 人工支持 |
| `clarify` | 需要更多信息 |
| `refuse` 或 **拒答** | 系统拒绝提供答案 |

并非每条回复都有引用或置信度分数。例如，向你索要订单号的请求就不需要文档引用。

## 查询订单

只有在你的组织已启用并连接订单查询时，该功能才可用。

1. 在会话中请求订单状态，并在同一条消息中包含你的订单号。
2. 如果被要求澄清，请在请求中再次提供准确的订单号。
3. 仔细阅读回复。消息说查询已被受理，意味着查询仍在进行中。
4. 留出处理时间，然后刷新浏览器并重新打开同一会话以查看结果。
5. 如果没有结果，或 AskFlow 无法核实订单，请携带订单号和受理消息联系支持。

后台结果会保存到会话历史中，但当前对话界面不会自动接收每一条后台更新。标准界面中没有单独的 **我的任务** 页面。

系统必须能够将订单与你的客户身份匹配，并获得可用的状态。结果标记为 **mock** 或模拟的是演示数据，不是真实订单状态的确认。缺少连接或结果无法核实，都会使请求保持未决状态。

在客户后续消息之后自动继续已保存的任务尚未完全接通。如果你补充信息后请求似乎卡住了，请让客服检查。反复发送同一请求并不是重启它的可靠方法。

## 请求人工支持

1. 发送“请帮我转接人工客服”或 **转人工客服**。
2. 留意 **已申请人工客服 (Human support requested)** 或等价的确认信息。
3. 留在同一会话中。等待期间你可以发送额外细节。
4. 客服回复到达后阅读它。如果没有出现，请刷新并重新打开该会话。

会话转接期间，自动助手会停止处理其中的常规请求。这样可以避免人工和助手各自独立作答。

**打开接管台 (Open handoff desk)** 是可能出现在横幅中的客服控件。客户无需点击它，普通客户账号也没有访问该工作台的权限。

可用性和等待时间取决于你的组织。如果无人认领的请求超时，系统可以创建一张高优先级工单，并将会话退回自动支持。请查看实际消息和 [你的工单](tickets.md)；这并不意味着客服人员已经回复或解决了问题。

## 更改或停止请求

请在同一会话中及时说明更正，并就已处理的请求联系客服。标准对话页面没有任务取消按钮，输入“cancel”也不是保证取消的操作。

你的组织可能提供单独的任务管理集成。请让支持通过该集成确认取消的结果。取消已保存的任务不一定能撤销已经发送到业务系统的操作。

关闭浏览器、退出登录、创建另一个会话或关闭工单都不会取消服务任务。

如果支持人员与你分享任务状态，请按如下方式理解：

| 状态 | 含义 |
| --- | --- |
| `active` | 工作仍在处理中 |
| `waiting_customer` | 需要客户信息；可能需要客服帮助恢复 |
| `waiting_external` | 正在等待已连接的服务、重试或外部确认 |
| `handed_off` | 责任已转交给人工；原问题不一定已解决 |
| `resolved` | 该任务的特定完成检查已通过 |
| `closed_unresolved` | 工作在未达到完成条件的情况下停止 |

登记工单的任务在工单存在后可以是 `resolved`。工单中描述的问题仍然需要跟进。
