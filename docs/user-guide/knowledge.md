# 知识管理

[用户指南](README.md) · 上一篇：[客服人员指南](support-staff.md) · 下一篇：[管理](administration.md)

本章需要管理员账号和相关的知识功能。

**知识库（knowledge base）** 是 AskFlow 在回答问题时可以查阅的信息集合。添加清晰、准确的信息会为它提供更好的处理材料。上传文档会使其内容可被搜索；它不会教会 AskFlow 执行新的业务操作。

## 准备你的第一份文档

使用 UTF-8 纯文本文件（`.txt`）或 Markdown 文件（`.md` 或 `.markdown`）。Markdown 是带有可选标题和列表的普通文本。纯文本编辑器可以创建任一格式。

当前的解析器读取文本。尽管上传区域说它支持常见文档格式，但它没有实现可靠的 PDF、Word、电子表格、图片或扫描文档提取。请将相关文本导出或复制到文本文件中，然后在上传前检查结果。仅仅把 PDF 重命名为 `.txt` 并不会转换它。

为了获得有用的源材料：

- 给文档一个清晰的标题，并在相关时包含生效日期。
- 陈述实际政策、其条件、例外情况，以及客户应采取的步骤。
- 使用明确的名称，而不是“此服务”或“上述”等含糊措辞。
- 将相关问题和答案放在一起。
- 在添加之前解决相互冲突或过时的政策。

只上传你的组织打算让 AskFlow 在客户回答中使用的内容。标准界面没有逐份文档的受众选择器。

## 上传并检查文档

1. 打开 **Admin → 知识文档 (Knowledge documents)**，或访问 `/admin/documents`。
2. 在 **上传并索引 (Upload and index)** 中，先输入可选的 **标题 (Title)**，再选择文件。如果省略，则使用文件名。
3. 点击上传区域选择文件，或将一个文件拖入其中。
4. 等待：选择或拖入文件会立即开始上传。你无需再次点击单独的 **上传并索引** 按钮。
5. 在 **文档列表 (Document list)** 中找到该文档。点击 **刷新 (Refresh)** 更新其状态。
6. 等待 **启用 (`active`)**，并检查 **分块 (Chunks)** 大于零。
7. 返回 **用户台 (User workspace)**，开始新会话，并提出一个答案出现在该文档中的问题。
8. 打开答案的引用，检查使用的是正确的来源和段落。

默认上传限制为 15 MiB，约 1570 万字节，但你的安装可能使用不同的限制。一次上传一个文件。如果上传失败，请在再次尝试前检查列表，以避免不必要的重复。

**索引（Indexing）** 指为搜索准备文本。**分块（Chunks）** 是搜索时使用的文档较小片段。更多分块并不自动意味着文档更好。

| 状态 | 含义 | 该怎么办 |
| --- | --- | --- |
| **待处理 / `pending`** | 正在等待处理 | 稍等片刻后刷新 |
| **索引中 / `indexing`** | 正在处理 | 等待；避免重复上传 |
| **启用 / `active`** | 处理已完成 | 检查分块数量，并尝试一个已知问题 |
| **失败 / `failed`** | 处理失败 | 检查文件，必要时联系安装运维人员 |
| `archived` | 记录被标记为已归档 | 向负责该内容的管理员询问其预期用途 |

一份 `active` 但分块为零的文档没有可供搜索的有用段落。二进制文档上传成功也不能证明其内容被正确提取。

## 替换过时信息

上传页面会为每次上传创建一份新文档。再次上传相同文件名不会自动替换之前的文档，也不会为其添加版本。

请准备更正后的文件，并安排替换，以免客户面对相互冲突的政策。页面可用的操作是上传和删除；没有 **替换 (Replace)** 或 **重建索引 (Reindex)** 按钮。对于必须保留同一文档版本历史的更新，请让你的技术运维人员使用受支持的维护接口。

要删除文档，找到正确的行并点击 **删除 (Delete)**。此操作立即生效，从知识集合中移除该文档，并且不是移入可见的回收站。请保留你自己的源文件副本。删除来源不会重写已保存在会话中的答案。

## 比较版本并回滚

有些文档保留了来自较早处理或维护工作的修订快照。**Gen** 或 **代（generation）** 是文档的修订号。

1. 在文档上点击 **版本 (Versions)**。
2. 阅读 **当前 generation (Current generation)** 和 **历史版本 (Historical versions)** 列表。
3. 如果至少有两个版本，在 **from** 中选择较早的版本，在 **to** 中选择较晚的版本。
4. 查看自动加载的比较：未更改、新增和移除的分块。**差异 (Difference)** 按钮是禁用的，因为比较会根据所选内容自动加载。
5. 如果需要恢复以前的版本，请点击目标历史版本旁的 **回滚 (Roll back)**。
6. 刷新文档列表，并再次测试一个相关问题。

回滚会立即更改可搜索内容，并从所选快照创建一个新 generation。它不会抹除较新的历史。如果没有快照，抽屉无法恢复较早的文件；请使用你保留的源文件副本或联系运维人员。

## 查看未回答的问题

打开 **Admin → 知识缺口 (Knowledge gaps)**，或访问 `/admin/gaps`。

缺口是一条被记录下来的问题，AskFlow 对其缺乏有用知识。**命中 (Hits)** 表示该分组问题被记录的频率。请先查看高频缺口，但也要检查它们是否属于你的服务范围。

- **忽略 (Dismiss)** 将缺口标记为已忽略。用于你不打算覆盖的问题。它不会教 AskFlow 答案。
- **生成草稿 (Generate draft)** 根据该问题创建草稿。在当前界面中，草稿正文就是问题本身；该操作不会生成已验证的答案。

不要把仅含问题的草稿当作包含答案的草稿来批准。草稿界面没有编辑现有草稿的控件。请拒绝这个占位草稿，并创建一个包含已验证答案的新草稿，或让运维人员使用可用的集成工作流。另外创建的替换草稿不会自动关联回原始缺口；请单独查看该缺口。

## 编写并发布有用的答案

1. 打开 **Admin → 知识草稿 (Knowledge drafts)**，或访问 `/admin/drafts`。
2. 在 **新建草稿 (New draft)** 中，输入描述性的 **标题 (Title)**。
3. 在 **正文 (Body)** 中，编写完整、经过验证的答案，包括适用条件。
4. 点击 **创建草稿 (Create draft)**。
5. 在列表中查看该草稿。发布前确保内容准确。
6. 点击 **通过 (Approve)** 发布它，或点击 **拒绝 (Reject)** 拒绝它。
7. 对于已批准的草稿，打开 **知识文档**，刷新并检查生成的文档。提一个示例问题并查看引用。

列表只显示 80 个字符的摘要，没有完整正文查看抽屉。请在创建前查看完整文本，保留源文件副本，或在批准不是你编写的草稿前，向运维人员索取完整存储内容。

**通过** 既是批准也是发布：它会立即创建并索引一份知识文档。没有额外的发布按钮。**拒绝** 会让草稿保持未发布。要更正已发布的草稿，请管理其生成的文档；更改草稿状态不能替代撤回已发布的内容。

## 有用的维护例程

每次内容更改后，查看新缺口、核实常用政策、移除过时或重复的文档，并测试有代表性的问题。对于错误答案，请先检查被引用的段落：来源本身可能需要更正。
