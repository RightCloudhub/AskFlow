# 其他对话方式

[用户指南](README.md) · 上一篇：[报表与服务监控](reports.md) · 下一篇：[隐私与已保存偏好](privacy.md)

你的组织可能会以网站聊天窗口或通过即时通讯应用提供 AskFlow。这些被称为 **渠道（channels）**：联系同一支持服务的不同地方。

请向你组织询问它实际连接了哪些渠道。产品中列出的渠道并不意味着它在每个安装上都可用。

## 使用嵌入式网站对话

**微件（widget）** 是放置在另一个网站内的小型聊天窗口。它可能显示 **AskFlow 在线客服 (AskFlow online support)** 和 **访客通道 (Visitor channel)**。

1. 打开组织网站上提供的支持窗口或链接。
2. 等待消息输入框变为可用。
3. 在 **输入问题… (Enter a question…)** 中输入你的问题。
4. 点击 **发送 (Send)**，或按 Enter 提交。
5. 阅读回复，并在同一窗口中继续。

微件会创建访客会话，无需常规注册表单。它的显示比主工作区更简单：不显示会话侧边栏、工单页面、置信度徽章或引用抽屉。答案文本中仍可能包含引用标记。

访客会话保存在此浏览器标签页的会话存储中。刷新同一会话可以重新加载其消息历史，但关闭标签页、清除浏览器数据或更换浏览器/设备可能会丢失重新打开它所需的本地信息。这不会删除服务器上存储的会话。

微件没有登录、退出或自助会话恢复控件。如果你的访客会话过期或微件无法重新连接，请联系网站的支持团队并描述错误。保留你后续跟进所需的任何工单或请求参考号的副本。

后台回复和客服回复可能需要刷新微件。如果组织不通过嵌入式窗口提供这些更新，请询问如何跟进请求。

## 使用飞书、企业微信或钉钉

AskFlow 包含对 **飞书 (Feishu)**、**企业微信 / 企微 (WeCom)** 和 **钉钉 (DingTalk)** 的集成支持。你的组织必须先配置其机器人和回复送达，才能依赖该渠道。

1. 打开你的组织指定的机器人或支持会话。
2. 遵循其关于私信或在群组中 @ 机器人的说明。
3. 发送文本问题，包含相关细节。
4. 被要求澄清时，在同一话题或会话中继续。
5. 如果请求已被受理但你没有收到结果，请通过组织声明的备用渠道联系支持。

对于 AskFlow 必须理解的信息，请使用文本。有些集成可以记录附件已发送；这并不意味着系统会读取其图片、文件、音频或视频内容。请用文字描述问题，并遵循组织关于发送辅助文件的说明。

格式、引用和可用操作与网页工作区不同。不要假设即时通讯应用中的编号引用会打开网页引用面板。

当前集成不保证客服回复或之后的后台结果会自动送达每个即时通讯应用。机器人收到消息也不能证明其出站回复连接可用。如果你看到反复没有回应，请询问支持，而不要多次发送同一请求。

## 理解跨渠道的账号

网站登录、微件访客和即时通讯应用用户可能被视为不同的客户身份。标准界面没有关联账号按钮或合并的跨渠道历史界面。

如果你切换渠道，请提供较早请求的参考号，并说明它从哪里开始。不要仅仅因为显示名称相同就假设 AskFlow 能匹配订单或工单。你的组织可能需要验证身份或配置该关联关系。

## 给负责配置渠道的人

当前管理界面没有渠道设置向导。请将适当的 [飞书检查清单](../../deploy/checklists/feishu-channel.md) 或 [企业微信和钉钉检查清单](../../deploy/checklists/wecom-dingtalk-channel.md) 交给技术运维人员。在与客户分享该渠道之前，请在实际渠道中测试接收、可见回复和后续送达。
