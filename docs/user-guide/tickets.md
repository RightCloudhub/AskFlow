# 你的工单

[用户指南](README.md) · 上一篇：[与 AskFlow 对话](chat.md) · 下一篇：[客服人员指南](support-staff.md)

**工单（ticket）** 是需要跟进的问题的记录。它让问题在对话结束后仍然可见。创建工单并不意味着底层问题已经解决。

## 打开你的工单

点击会话侧边栏中的 **工单 (Tickets)**，或打开你的 AskFlow 网站上的 `/tickets`。**我的工单 (My tickets)** 页面显示与你的登录账号关联的工单。

如果该链接不存在，可能是该功能未启用。访客对话或即时通讯应用身份可能有不同于你网站账号的记录；如果工单似乎丢失，请询问支持。

## 创建工单

1. 找到 **新建工单 (New ticket)**。
2. 输入简短而具体的 **标题 (Title)**，例如“支付页面显示 E12”。
3. 在 **描述 (Description)** 中说明发生了什么、何时发生、你期望什么，以及你已经尝试过什么。
4. 点击一次 **提交 (Submit)**。
5. 确认该工单出现在列表中。

例如：

> 标题：支付页面显示 E12  
> 描述：10 月 4 日大约 10:30，我点击“支付”后，支付页面显示 E12。我又试了一次，看到相同消息。请帮我检查订单是否已创建。

请使用你的真实信息，并在相关时包含订单号或参考号。不要包含密码或完整的支付卡信息。

客户表单有标题和描述字段。它不提供附件、优先级选择器、客服分配或可编辑的讨论串。

根据请求和已启用的功能，AskFlow 也可能从对话中创建工单。在创建另一张之前请先检查列表。当你有未关闭的工单时，提交相同标题可能会返回现有工单；它不一定会创建第二条记录或更新原始描述。

## 阅读状态

| 显示的状态 | 含义 |
| --- | --- |
| **待处理 / pending** | 工单正在等待处理 |
| **处理中 / processing** | 客服已将其标记为正在处理 |
| **已解决 / resolved** | 客服已将该问题标记为解决 |
| **已关闭 / closed** | 工单已被关闭 |

优先级描述紧急程度。你可能看到 `low`、`medium`、`high` 或 `urgent`。客户页面显示优先级，但不允许你更改它。如果影响或紧急程度发生变化，请告诉支持。

工单状态、会话状态和后台任务状态是相互独立的。工单仍在处理时，会话可以回到自动对话。

## 在列表和看板之间切换

- **列表 (List)** 显示一个表格，包含标题、状态、优先级、创建时间和关闭操作。如果记录多于一页，请使用页面控件。
- **看板 (Board)** 将相同的工单按状态分组到列中。点击工单卡片以打开 **工单详情 (Ticket details)** 并阅读其描述、类型、优先级和创建时间。

看板是一种查看工具。拖动卡片不会将工单移动到其他状态。

刷新页面以查看客服所做的更改。客户工单列表不提供实时进度推送，也不保证电子邮件通知。

## 关闭你的工单

1. 确认你不再需要就该问题继续跟进。
2. 切换到 **列表 (List)**。
3. 找到正确的工单并点击 **关闭 (Close)**。
4. 确认其状态变为 **已关闭 (Closed)**。

当前的关闭按钮会立即生效。没有单独的确认对话框或客户重新打开按钮。如果你误关了工单，请联系支持并说明该工单；客服人员可以就后续处理给出建议。

关闭工单不会发起退款、撤销付款、取消订单或停止后台任务。这些操作请使用你组织的特定流程。

## 提交后补充信息

客户工单界面不提供编辑或评论。使用 **返回对话 (Back to chat)** 回到相关会话，说明更正内容，并通过标题和创建时间指明该工单。如果更新必须传达给正在处理问题的人，请请求人工支持。

如果你在工单丢失或提交失败方面需要帮助，请参见 [故障排查](troubleshooting.md)。
