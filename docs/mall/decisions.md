# 推荐默认值、风险与上线决策

2026-10-29 用户 `keep going` 后按以下推荐值继续，保留 code only。M0 不再阻塞后续编写；以下真实业务/部署决策仍需在上线前由运营/财务确认，不把时间流逝当批准。

| 事项 | 推荐实现默认值 | 真实上线仍需确认 |
|---|---|---|
| 币种/限额 | CNY，整数分；商城自动退款上限5000分；无FX | 币种、免审批额度、税费/发票口径、退款法律期限 |
| 邀请 | 单层；验证手机号；首单完成后7天发奖；提现关闭 | 发奖金额/比例、每日累计上限、风险误伤处置、已花奖励追偿政策 |
| 部署 | mall 演示，mall-lite 单容器，mall-only 无AI工单 | 公网注册显式 opt-in、SMTP/SMS供应商、生产容量与保留期 |
| 支付/物流 | mock HMAC网关、mock物流，接口为真实网关预留 | 支付机构、商户凭据、真实回调/对账、退款和物流连接器 |
| 默认运费/优惠 | 运费0、无优惠；服务端计价，后续typed设置 | 地区费率、税率、优惠叠加/退款分摊规则 |
| 权限 | 超管/运营/客服/财务/只读审计；调账双人复核 | 超管账号配置、职责分离、审批替岗/紧急流程 |
| 财务保留 | 停用脱敏，订单/分录不删除；保留年限不硬编码 | 适用司法辖区、会计档案/隐私期限、备份擦除策略 |

## 风险及处置

| 风险 | 设计措施 | 验证/边界 |
|---|---|---|
| 用户通过旧登录绕过商城MFA/吊销 | 共享密码/安全入口和JWT/WS校验 | 旧接口、OIDC、WS越权矩阵必须新增；不修改旧profile无安全记录用户行为 |
| SQLite StaticPool 单连接并发“看似通过” | 业务测试内存fixture；并发另用文件SQLite多连接 | 不拿单连接 asyncio.gather 证明数据库竞争 |
| 退款/支付外部超时未知 | 意图先提交、永久业务key、查询补偿 | mock可验证，真实支付连接器未实现前不宣称真实生产退款 |
| 钱包链分叉/账户死锁 | 独立currency链头、稳定锁顺序、CAS | 200并发、篡改、DB故障/事务回滚测试 |
| Redis故障导致多实例进程锁 | staging/production拒绝不安全组合 | 不自动切memory；演练显式PG/DB降级部署 |
| 配置事件只送一个实例 | 广播失效+版本读取+短TTL | 多实例热更新测试；不热改Harness常量 |
| webhook重复/金额篡改/乱序 | HMAC、时间窗、唯一流水、server比对、单次记账 | 100回调、伪造和late_payment测试 |
| 设备/IP关联误伤真实家庭/公司 | 仅风险信号、阈值、人工review | NAT共享和支付账户关联测试，规则可审计回滚 |
| 压测目标与当前硬件不符 | 保存规格/配置/数据/报告，首次校准 | 全部指标当前未测；不得填造QPS/P99 |
| 新迁移错误影响原客服 | 冻结schema/双向双方言、独立bootstrap | 空库/既有create_all库/旧migration库三矩阵 |
| 无运行验证导致静态编写风险 | 分阶段小变更、完整待运行清单、诚实STATUS | 本轮不能提供通过率/覆盖率/可部署验收证据 |

真实 PostgreSQL 主从部署不等于自动故障切换。控制面商城设置不等于全部 AskFlow 目标/模型/策略控制面已完成。按 STATUS 分开记录，不替换历史证据。
