## 兼容与资金边界

- 原 full/enterprise/mvp/faq-only/core-only 插件列表未加入商城。新增 mall、mall-lite、mall-only；mall_support 的 Agent 依赖按条件装配，以保留无AI档工单能力。
- users 列语义保留，扩展信息写新表。商城开启时旧本地登录／注册提示使用商城认证入口，避免绕过 MFA；原档继续原路径。OIDC继续复用原身份绑定。
- 最早冻结客服基线解决空库治理迁移提前引用 users 的问题，旧修订ID保留。基线 downgrade 有意保留原客服表；商城 downgrade 仅删除商城表。**尚未执行双方言迁移验证。**
- 金额为整数分；支付和退款只接持久化 mock。mock 的退款能实际推进订单和分录，但不等于真实支付机构退款。当前不允许把网络网关直接换进同事务 mock 路径。
- 每币种链头串行追加，正确性优先；吞吐目标可能受此锁限制。调账／冲正需两人，差异复核不改原证据。没有自动快照重建接口。
- 外部发送可重复：数据库站内通知按事件去重；SMTP/外部供应商若发送成功而DB提交失败，仍需供应商幂等或人工核对，不能承诺跨系统 exactly-once。

## 尚未满足的规格项

1. 注册奖励默认关闭，注册/首单奖励均延迟到首单完成并过售后期；付款关联信号目前来自 mock HMAC 回调。真实供应商信号、手机号段地区口径和风控误伤率未经校准。
2. 浏览器OIDC供应商授权跳转／PKCE流程未新增；API提供既有 ID token 交换并补 MFA。真实供应商、物流、提现、复杂售后、游客购物车合并未交付（后几项按原要求可选／后置）。
3. 测试已覆盖若干关键一致性路径，但完整全模块验收、每种可选适配器合约／故障矩阵及覆盖率目标尚无证据，不能仅凭测试文件数量称完成。
4. 自动 PostgreSQL 故障切换未实现。full compose提供静态复制拓扑；k8s full依赖预置的外部状态服务与凭据。
5. 搜索超出有界候选会降级LIKE；没有大规模ES search_after相关性分页。配置缓存逐次查主库版本保证收敛，尚未压测其读开销。
6. 本轮不满足“阶段测试全绿／构建通过／性能达标／部署验收通过”的完成定义；这些与用户当前禁止运行的指令冲突，已统一留待验证。
