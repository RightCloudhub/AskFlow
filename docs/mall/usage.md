# 用户与管理员使用说明

此文对应已编写的界面／接口，尚未执行演示验收。完整运行前先按 [验证清单](validation.md) 检查迁移、安全配置和构建。

## 本地演示

`infra/compose/lite/docker-compose.yml` 提供单容器 API、打包网页和 SQLite 卷。开发演示收件箱仅在 development 且显式开启时可见，生产不允许使用。访问 `/shop/account` 注册：发送验证码、查看本地演示验证码、验证并创建账号，再以用户名／邮箱／手机号登录。短信渠道同样可以用国际格式手机号验证；console 不真实外发。

首次后台管理员使用 `python -m app.commerce.admin.bootstrap --username admin --email admin@example.com`，在 API 容器中交互输入密码。先完成迁移；若已有管理员，使用既有身份，不会再创建第二个 bootstrap 管理员。该命令及以下步骤均未在本轮执行。

管理员也从 `/shop/account` 登录，再访问 `/admin/mall/dashboard`。在商品页创建 SPU 和 SKU，设置整数分价格；库存页入库，最后将 SPU 与 SKU 都设为 active。后台操作所需编号和 version 从表格获取；版本冲突后刷新再审阅，不盲目覆盖。

客户在商品详情选 SKU、加购、选择地址、核对金额并确认下单。订单详情支持 mock 或钱包组合支付；大额支付展开身份验证。模拟支付成功仅改变测试网关状态，不扣真实银行卡资金。发货、送达、完成由运营状态迁移控制，已发货订单客户可确认收货。

取消未付订单需要二次确认。申请退款先确认金额和目的地，超过自动退款限额的申请还需运营审批；退款成功由后台 worker 推进，不能把“已申请”当成到账。钱包充值同样需要模拟网关成功后才能入账。

## 账号、消息和客服

账号页可修改资料／头像、管理收货地址、查看会话并下线设备、改密、绑定新联系方式、开启 TOTP 和保存恢复码。恢复码只展示一次；启用 MFA、改密／重置后重新登录。换绑需要旧目标和新目标分别验证，并取得对应 step-up。

订单、售后、钱包流水的联系客服入口携带资源引用。创建客服会话时服务端重新检查归属，可以同时创建工单／人工转交。启用 Agent 的档位可说“我的订单 <订单号> 到哪了”、“取消订单 <订单号>”、“退款订单 <订单号>”；取消／退款仍有确认步骤。mall-only 保留工单与人工入口，不能承诺 AI 对话能力。

“消息与客服”汇总站内信与会话／工单引用；订单、退款、工单变化由 outbox 投影。邮件／短信关闭时站内信仍可用。通知模板只插入白名单字段，例如 `订单 {{order_id}} 已更新为 {{status}}`，不执行表达式或模板代码。

## 财务与权限

后台财务页区分账户、调账申请、冲正申请、对账批次和差异。调账及冲正需要申请人和另一名批准人分别进行身份验证。不得把两套权限授予同一人就当作完成双人复核；后端仍检查操作者不同。

差异复核填写外部处置凭证和原因，只把状态标成 reviewed，expected/actual 原始证据保留。它不会自动修复余额。重新运行对账确认问题是否解决；快照重建需专项维护流程，不能直接改 journal/posting。

超级管理员可配置内置角色授予，或创建自定义角色并填写权限代码。可编辑配置仅限运费、退款限额、邀请阈值、通知频率等白名单项；支付密钥、数据库、基础设施预设与 Harness 不可由运营表单修改。

邀请码支持单层首单完成后延迟奖励；可另开注册奖励，但同样先待发、首单完成并过售后期才入账。同设备／IP／手机段／付款摘要和未验证手机号可能进入复核，退款后按账务冲正或记录追偿。付款身份目前是 mock 信号，真实推广前需校准规则和供应商契约。

注销前必须清空可用／冻结钱包并完成未决订单与支付；停用后不能登录。历史订单和财务引用保留、个人资料脱敏，保留期限由上线政策决定。
